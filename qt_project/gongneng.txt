================================================================================
                    SMART RIDE 智能骑行码表 — 功能开发总规划
================================================================================
项目定位：基于树莓派5B + STM32 的带屏智能码表
数据链路：STM32(采集) → 串口 → 树莓派PyQt(显示/智能/存储) → 蓝牙/WiFi → App
当前状态：核心UI、语音、大模型、在线地图已完成；通信层和数据持久化层待补齐
================================================================================


【一】当前已实现功能清单（基础层）
────────────────────────────────────────────────────────────────────────────────

1. [完成] PyQt5 主界面系统
   - 速度表、功率表（自定义 CircleGauge 控件）
   - 右侧数据卡片：踏频、距离、时间、坡度、温度、心率、后方距离
   - 顶部状态栏（WiFi状态、时间、页面切换）
   - 消息/对话显示区（支持多行、流式输出）

2. [完成] STM32 串口数据采集
   - 串口 /dev/ttyAMA2 读取
   - JSON 格式数据解析
   - 数据实时刷新到 UI 和 DataContext

3. [完成] 高德在线地图
   - Web 地图嵌入（JS API）
   - 实时位置标记
   - 省份变化自动检测与显示
   - 基础导航信号框架（开始/结束/指令回调）

4. [完成] 离线语音系统
   - Piper 本地 TTS 引擎封装
   - Edge-TTS 在线回退（混合播放器 HybridVoicePlayer）
   - 多种播放器降级策略（ReSpeaker/AOSS/PyAudio/pygame/pyttsx3）
   - 欢迎语音自动播报

5. [完成] 按钮语音交互
   - ReSpeaker 物理按钮触发（GPIO 17）
   - 按住录音、松开发送
   - LED 状态指示（呼吸灯/红/绿）

6. [完成] Ollama 本地大模型问答
   - 自动检测 Ollama 服务并启动
   - 自动选择可用模型（my-llama/llama3.2/qwen 优先级排序）
   - 支持极速模式、异步模式、流式输出
   - 超时 30s（极速）/ 60s（流式）

7. [完成] 数据上下文管理器 (DataContextManager)
   - 单例模式线程安全
   - 维护速度、功率、踏频、距离、时间、坡度、温度、心率、后方距离、位置
   - 自动生成自然语言描述（供大模型作为 system prompt 上下文）

8. [完成] 位置服务
   - 离线省份判断（基于坐标反查）
   - 语音播报"进入XX省"

9. [完成] 串口调试器
   - 串口日志重定向到 /dev/ttyAMA10，方便外接调试

【三】详细开发步骤（按先后顺序，不可跳跃执行）
────────────────────────────────────────────────────────────────────────────────

────────────────────────────────────────────────────────────────────────────────
★ 阶段0：项目结构重构（所有后续步骤的前置条件）
────────────────────────────────────────────────────────────────────────────────

步骤 0.1  代码目录重构
  前置：无
  内容：将当前单文件堆叠的代码拆分为分层架构
  产出：
    ├── main.py                # 入口仅存初始化
    ├── ui/                    # UI 页面、控件、QSS
    ├── core/                  # DataContext、协议模型、工具函数
    ├── services/              # 业务服务层（通信/骑行/告警/AI）
    ├── drivers/               # 硬件驱动层（串口/BLE/WiFi/音频）
    ├── persistence/           # 持久化层（文件/配置/数据库）
    └── llm/                   # 大模型客户端与提示词模板
  依赖：阶段0必须在阶段1之前完成

步骤 0.2  定义统一数据协议
  前置：步骤 0.1
  内容：定义 STM32 → 树莓派的 JSON 协议规范，以及树莓派 ↔ App 的通信协议
  产出：protocol.py（包含数据结构 RideDataPacket、CommandPacket）


────────────────────────────────────────────────────────────────────────────────
★ 阶段1：通信基础层（当前最大缺口）
────────────────────────────────────────────────────────────────────────────────

步骤 1.1  BLE 外设模式（BLE Peripheral）
  前置：步骤 0.2
  内容：
    - 使用 bluez/bleak 让树莓派作为 BLE GATT Server
    - 创建自定义 Service（如 0xFF00），包含 Characteristics：
      * 实时数据通知（Notify）：速度、心率、功率、踏频、GPS
      * 骑行状态（Read）：开始/暂停/结束
      * 设备信息（Read）：电量、固件版本
  产出：drivers/ble_server.py
  依赖：步骤 1.1 必须在步骤 1.3 之前完成

步骤 1.2  WiFi 数据通道（WebSocket Server）
  前置：步骤 0.2
  内容：
    - 树莓派启动 WebSocket Server（端口 8765）
    - App 连接后订阅实时数据流
    - 支持历史记录批量下载、设备配置下发
  产出：drivers/wifi_server.py
  依赖：步骤 1.2 必须在步骤 1.3 之前完成

步骤 1.3  通信调度器（CommService）
  前置：步骤 1.1、1.2
  内容：
    - 统一调度 BLE 和 WiFi 两条通道
    - 根据连接状态自动选择主通道（BLE优先省电，WiFi传大文件）
    - 管理 App 连接/断开事件
  产出：services/comm_service.py
  依赖：步骤 1.3 是阶段1的核心产出，是阶段2的前提

步骤 1.4  断连缓存与补发
  前置：步骤 1.3
  内容：
    - 当 BLE/WiFi 断开时，骑行数据写入本地环形缓存队列
    - 重连后按时间戳顺序批量补发
    - 缓存上限 30 分钟或 5000 条数据
  产出：persistence/buffer_queue.py
  依赖：步骤 1.4 建议在阶段1末尾完成

步骤 1.5  协议转换（标准 FIT / GATT / Protobuf）
  前置：步骤 1.3
  内容：
    - BLE 通道发送标准 CSCS/CPS/HRS GATT 数据（让 App 像连普通传感器一样识别）
    - WiFi 通道使用 Protobuf 或 JSON 压缩传输
    - 导出标准 FIT/GPX 文件格式
  产出：core/protocol_converter.py
  依赖：步骤 1.5 为阶段2的 FIT 存储做准备


────────────────────────────────────────────────────────────────────────────────
★ 阶段2：数据持久化与安全告警
────────────────────────────────────────────────────────────────────────────────

步骤 2.1  本地骑行记录存储（FIT/GPX 文件）
  前置：步骤 1.5
  内容：
    - 每次"开始骑行"时创建新的 FIT/GPX 文件
    - 实时写入轨迹点（时间戳、坐标、速度、心率、功率...）
    - "结束骑行"时关闭文件并计算统计摘要
  产出：persistence/ride_repository.py
  依赖：步骤 2.1 是阶段2的基础，必须在 2.2 之前完成

步骤 2.2  骑行会话管理（RideService）
  前置：步骤 2.1
  内容：
    - 开始/暂停/恢复/结束骑行按钮逻辑
    - 骑行时间累计（排除暂停时间）
    - 骑行距离、平均速度、最大速度、爬升计算
    - 联动 FIT 文件打开/关闭
  产出：services/ride_service.py
  依赖：步骤 2.2 必须在 2.4 之前完成

步骤 2.3  历史记录管理页面
  前置：步骤 2.1
  内容：
    - PyQt 新增"历史"页签
    - 骑行列表（日期、距离、时间、平均速度）
    - 点击详情可查看统计和轨迹回放（在地图上显示历史 GPX）
    - 支持 FIT/GPX 文件通过 WiFi 发送给 App
  产出：ui/history_page.py
  依赖：步骤 2.3 依赖 2.1，但可与 2.2 并行

步骤 2.4  智能安全告警系统
  前置：步骤 2.2（需要准确的骑行状态中判定异常）
  内容：
    - 后方来车告警：rear_dist < 5m 时语音+LED 红灯闪烁告警
    - 心率异常告警：心率超过用户设置上限（默认 180bpm）时语音告警
    - 疲劳告警：连续骑行超过 4 小时提醒休息
    - 跌倒检测（可选）：如果 STM32 未来上传加速度数据，增加速度骤降+姿态异常判断
  产出：services/alert_service.py
  依赖：步骤 2.4 是阶段2的核心产出

步骤 2.5  用户配置管理
  前置：步骤 2.4
  内容：
    - 保存用户偏好：心率上限、年龄、体重、默认单位、BLE设备白名单
    - 设置页面入口
  产出：persistence/config_manager.py、ui/settings_page.py
  依赖：步骤 2.5 为后续功能提供配置支撑


────────────────────────────────────────────────────────────────────────────────
★ 阶段3：离线智能增强（导航 + AI Agent）
────────────────────────────────────────────────────────────────────────────────

步骤 3.1  离线地图瓦片系统
  前置：无（可与阶段2并行）
  内容：
    - 将高德在线地图升级为支持离线瓦片缓存
    - 使用 OpenStreetMap 瓦片 + MBTiles 格式（SQLite 打包）
    - 开发瓦片预下载脚本 tools/download_tiles.py（给定边界框和层级批量下载）
    - MapWidget 优先读取本地瓦片，无本地时尝试网络下载并缓存
  产出：persistence/tile_cache_manager.py、scripts/download_tiles.py
  依赖：步骤 3.1 必须在 3.2 之前完成

步骤 3.2  离线导航引擎
  前置：步骤 3.1
  内容：
    - 路线规划：支持 GPX 路线文件导入（可由手机提前规划后传给树莓派）
    - 路线跟随：实时计算当前位置是否在路线上，计算偏离距离
    - 导航指令：在转弯前 50m/200m 生成语音提示指令
    - 语音导航播报：通过 Piper TTS 播报"前方左转"等
  产出：services/nav_engine.py
  依赖：步骤 3.2 是阶段3的核心，必须在 3.3 之前完成

步骤 3.3  AI Agent（语音控制设备）
  前置：步骤 3.2
  内容：
    - 扩展 AI 能力：不仅回答，还能执行系统操作
    - 意图路由：
      * "开始骑行" → RideService.start_ride()
      * "结束骑行" → RideService.stop_ride()
      * "导航回家" → NavEngine.plan_route_to_home()
      * "打开车灯" → GPIO 控制外部车灯继电器
      * "播报当前数据" → DataContext 内容 TTS 播报
      * 其他开放问题 → Ollama LLM 回答
  产出：services/ai_assistant.py（升级 ollama_client.py）
  依赖：步骤 3.3 建议在阶段3末尾完成


────────────────────────────────────────────────────────────────────────────────
★ 阶段4：扩展硬件与外设
────────────────────────────────────────────────────────────────────────────────

步骤 4.1  BLE/ANT+ 外设直连
  前置：步骤 1.1（已有 BLE 基础）
  内容：
    - 树莓派作为 BLE Central，直接扫描并连接心率带、功率计、踏频器
    - 解析标准 GATT 服务：Heart Rate (0x180D)、Cycling Power (0x1818)、CSC (0x1816)
    - 将 BLE 传感器数据合并到 DataContext（作为 STM32 数据的补充/备份）
  产出：drivers/ble_central.py
  依赖：步骤 4.1 可与阶段3并行

步骤 4.2  行车记录仪（DVR）
  前置：无（独立功能）
  内容：
    - 连接树莓派 CSI/USB 摄像头
    - 循环录制 H.264 视频（最大保留 2 小时，自动覆盖旧文件）
    - 通过 OpenCV 在视频画面上叠加骑行 OSD（速度、时间、GPS 坐标）
    - 紧急情况按钮保存当前 5 分钟视频不被覆盖
  产出：drivers/camera_dvr.py
  依赖：步骤 4.2 为高级扩展功能，优先级较低

步骤 4.3  功率训练课程模式
  前置：步骤 2.2（RideService 已支持骑行状态）
  内容：
    - 支持加载结构化训练文件（如 ZWO 格式或自定义 JSON）
    - 实时对比目标功率和实际功率
    - 语音提示："加大功率到 250 瓦"、"保持"、"休息 5 分钟"
    - 训练结束后生成完成度评分
  产出：services/training_service.py
  依赖：步骤 4.3 面向进阶用户，可后期再做


────────────────────────────────────────────────────────────────────────────────
★ 阶段5：云端、生态与高级功能
────────────────────────────────────────────────────────────────────────────────

步骤 5.1  云同步后端
  前置：步骤 2.1
  内容：
    - 骑行记录在有网络时自动上传到自建后端/对象存储
    - 断网时保存本地，有网时增量同步
    - 支持多设备数据合并、冲突处理（以树莓派本地时间戳为准）
  产出：services/cloud_sync.py
  依赖：步骤 5.1 需要后端配合开发

步骤 5.2  OTA 固件升级
  前置：步骤 1.2（WiFi 通道）
  内容：
    - App 推送 STM32 固件包到树莓派
    - 树莓派通过串口 Bootloader 或 SWD 给 STM32 刷机
    - 树莓派自身 Python 项目也支持远程更新（git pull / zip 包解压）
  产出：services/ota_service.py
  依赖：步骤 5.2 产品化后必须支持

步骤 5.3  电子围栏 / 防盗定位
  前置：步骤 2.5
  内容：
    - 停车模式：树莓派低功耗待机，GPS 关闭，震动传感器/位移检测开启
    - 检测到车辆被移动后，唤醒 GPS 记录轨迹，通过 WiFi/手机热点发送告警到 App
    - 日常可查看车辆实时位置
  产出：services/security_service.py
  依赖：步骤 5.3 涉及功耗管理，实现难度较高

步骤 5.4  组队骑行 / 多人对战
  前置：步骤 1.3
  内容：
    - 多台树莓派之间通过 WiFi Direct 或 BLE Mesh 组网
    - 实时共享队友位置、速度、距离
    - UI 显示队友相对位置（前方 500 米 / 掉队 1 公里）
  产出：services/group_ride.py
  依赖：步骤 5.4 为社交增值功能，周期长，放最后

【六】说明
────────────────────────────────────────────────────────────────────────────────

1. 阶段0（重构）必须做，否则后续代码会越来越难维护。
2. 阶段1（通信）是当前最大缺口，没有 BLE/WiFi，树莓派就无法和 App 形成闭环。
3. 阶段2（数据+安全）完成后，产品已经具备基本可用性。
4. 阶段3（离线智能）让产品在户外弱网环境下也能独立工作。
5. 阶段4/5 根据你的时间和资源决定是否继续投入。
